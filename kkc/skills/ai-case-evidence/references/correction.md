# 纠错闭环与章节证据索引

用户要求证明人工判断、纠错与验证，或真实任务发生退回修改时，读取本文件。只整理实际发生的过程；不为补分制造问题、重演已完成的历史或自动启动新业务批次。已有反馈与证据持续有效，AI负责回查、关联、整理，人只补缺失的判断与对应版本复验。

## 六步证据链

**原图及要求 → 不合格结果 → 本人指出的问题 → 修改方法 → 重新输出 → 人工验收。**

按具体问题串联同一素材和版本，必要时给问题一个短编号。至少能够回查素材标识、要求及来源、不合格版本、本人反馈原话与来源、实际修改、重输出版本、本人对该版本的复验结论和可信依据。不以“优化过”“检查通过”等笼统总结代替过程。

1. **原图及要求**：确认是哪张素材、哪一项要求、比较的区域。后续更换素材、规格或要求时说明变更，不能直接宣称为原问题已修复。图片任务用同一原片重跑并对照；其他任务用同一输入或说明可比较性。
2. **不合格结果**：保留实际失败版本及可读证据，定位问题。商品被裁断、人物位置偏移、背景接缝明显只是问题表达示例，只有真实出现才登记；不把示例当作本人反馈。
3. **本人指出的问题**：保留本人实际反馈及对应版本，说明问题由谁首先发现。AI自检发现、本人判断和本人转述分别注明；AI发现的问题不能改写为本人独立发现。只说“以后增加视觉检查”记录为计划。
4. **修改方法**：记录实际改了哪些裁切、主体位置、蒙版、图层、背景接缝或其他处理，必要时写修改前后参数。区分本人作出修改决定、本人亲手修改、AI执行修改；没有执行日志或版本差异时，不把建议写成已完成修改。
5. **重新输出**：登记重跑的实际输出版本、时间和与原素材的关联，保存前后对照及检查结果。未本人复验的重输出用既有`other`等适合角色登记，不提前标`final`；技术成功、AI自检通过仅作技术结果。
6. **人工验收**：记录本人实际查看的是哪一版、怎样对照原要求、结论和为什么可信。可用同素材前后图、问题区域放大、主体完整性/位置/接缝检查等实际依据。只有明确对该版的复验通过才描述该问题纠错闭环；“检查完成”仅结束计时，重新输出或AI自检不能代替本人通过结论。

闭环按问题、样本和版本记录。只复验一张时只写该张通过，不推广为整批通过；未关闭问题仍列待验证。后续换版时，旧结论只能证明旧版，实际复验新版本后再更新；未变化版本的已知确认不重复索要。相同素材重跑可证明纠错，不因此成为第二真实批次的复用证据。

## 状态与边界

按证据如实写“已反馈待修改 / 已修改待重输出 / 已重输出待本人复验 / 本人复验未通过 / 本人复验通过”。原始问题、实际修改或同素材版本关系不清时补“证据待核”，不要因为末尾有一句“可用”就回填整条历史链。只有可追溯反馈、实质修改、对应重输出和本人复验及可信依据具备时，才写已完成纠错闭环；仅有本人陈述时保留user_report及证据局限。

本人复验通过代表相应版本的质量确认，可据实登记`quality_status=usable`与`final`；业务采用、正式验收另看实际来源。没有业务采用不否定已经完成的质量纠错；也不能据质量确认自动添加业务`acceptance`。实际采用、正式验收、文稿内容确认、计时结束不互相代替。报告人工判断项主要依靠纠错证据，不因索引或文件齐全就自动判2分。

## 章节证据索引：四类材料

默认在报告或案例稿的相关章节中简要概括并链接以下四类材料，共用已有证据，不规定四个必交附件。某章材料多时统一放入该章的一份飞书证据文档，用文档内小标题分类，正文保留关键证据和该章证据链接；具体布局见[feishu-layout.md](feishu-layout.md)。默认不额外建立独立总索引，索引编稿与原始定位仍留在work。

| 材料类别 | 索引写什么 | 链接指向 |
|---|---|---|
| 原始素材与任务要求 | 素材/样本、实际要求、来源 | 对应原图/输入、任务消息或需求记录 |
| 关键反馈及修改记录 | 问题、本人原话、发现者、实际修改与执行者 | 不合格版本、反馈记录、操作或版本差异 |
| 最终文件与检查结果 | 对应版本、同素材重跑、问题区域对照、复验依据和当前状态 | 实际修订版/已复核终版、检查记录 |
| 实际验收或采用反馈 | 明确是本人质量复验、业务采用还是正式验收；无实际采用如实写明 | 对应版本的真实确认、采用反馈或验收记录 |

相关章节只需注明任务/素材、问题、当前状态，以及一行实际发生的六步链。每类用一两句并引用必要证据编号，不堆完整日志。同一文件可支持多个环节，说明所支持的事实；缺材料对应行写“待核/未发生”，不创建占位文件充作证据。真实尚缺事实合并为最重要1—3条，最多5条；由AI可回查的不用人重交。

链接按交付环境选择：聊天中的本地材料用可点击绝对路径；离线索引用随包存在的相对链接；线上文稿只引用已授权且可访问的真实链接，或在同一文档内嵌关键图证并链接到相应段落。不能把本机路径伪装成线上证据链接，也不为凑链接擅自上传材料。只有链接没有可读内容或访问权限时，应披露限制。

## 在案例稿和报告中如何写

把最完整的一条真实纠错过程写清楚即可：问题具体、修改确实发生、同素材/可比输入前后对照、本人如何复验及为何可信。其余问题用索引回查，不靠篇幅或问题数量堆分。使用报告按当前八节模板，在案例分析、产出清单及“问题与提升空间”引用对应证据，不添加人工判断预评分。未执行的“增加视觉检查”只能作为待验证的改善方向，不能当本期闭环；不另设提升建议或行动计划章节。
