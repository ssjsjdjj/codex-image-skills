# 质感、结构与 Logo 的批量选择

读 [review-contract.md](review-contract.md) 核对身份、状态和选择载荷。页面只记录范围；不具备图像编辑后端，不宣称点击即已修图。

## 选择入口

- 服饰默认优先展示质感/面料 Q，提供本图、本批次待修质感全选；只新增已确认、待处理且无未满足依赖的 Q，不选 R、未知状态或已完成项。
- 保留本图/本批次待修 Logo 全选，仅新增确认的 D/logo；其他结构 D 单独筛选，不能混入 Logo 全选。
- 全选当前筛选结果指完整筛选结果，不是屏幕内可见几张卡片；保留单项取消、反选和全部取消。
- 选择为追加；换筛选不清空，显示筛选外仍已选数量及完整清单。用户显式选择 Q/F 后再点 Logo 全选，不偷偷删除已有授权范围。
- 已修项返修需显式允许；显示技术通过、待复核和用户采用的区别。证据不足和未知状态不转成默认待修，补证确认后通过状态记录更新。

自然语言“本图质感都修”“本批次已确认 Logo 都修”“全修除去某人/编号”可直接展开。先核对当前批次、图片/人物、有效版本和实际编号，告知数量后执行既有授权，不重复逐项确认。指代确实不明时只澄清缺失点。

## 生成与接收

```bash
python scripts/build_bulk_review.py --manifest 检查清单.json --output 批量选择.html
```

历史状态必须有可验证批次和定位，按数据契约传入 `--status-record`；不能按裸 D01/Q01 合并不同案例。生成器校验字段与关联，记录实际图片内容指纹。报告、页面和机器状态来源保持一致。

复制指令与下载 JSON 使用相同选择载荷，带 schema、批次、修订、源清单摘要、每项图片/人物/类型及输出绑定；不能只复制编号。接收后用脚本校验入口重新核验当前实际文件和定位，不能只信导出时的摘要。跨批、过期、换图或定位变化时拒绝整份载荷并给出具体原因；排除或修正错误项后，重新校验其余已授权项，不能把未报错项视为自动部分放行。

同图已有修复应继承当前有效基线和用户选定版本；失败只撤回本次候选，不覆盖此前有效的面料、领口、标识等。状态撤回时同步更新清单和展示，新输出不继承旧输出 QA/采用。

旧版清单可只读显示并带诊断；旧无身份状态记录不自动继承完成。只有图片、对象、参考和输出唯一对应可证明时才迁移，原编号与历史说明保留；无法证明则需复核，不把它变成新的修复授权。
