# 尺寸调整个人规则初始模板（3.4，需本账号确认）

- 默认铺满目标画布，无新增白边或透明边，保持等比，不拉伸。
- 先确定本批主要售卖商品和要突出的特性，再逐图设置焦点、裁切框和保护范围；不把固定居中、统一放大或统一人脸定位当作自然构图。
- 默认review_mode=batch，取得所需后端选择后一次生成整批全部预览，同尺寸放一起，每size给1—N编号总览。用户可集中确认或点名某尺寸第N张调整，按groups映射全局index后修改并刷新预览/digest；最新整批真实确认后才正式生成，不伪称逐张人看。旧单张流程仅用户明确要求时用。单次确认不自动形成长期偏好。
- 每批主体单独选择；用户已明确品类或明确要求沿用上批主体时直接采用。目录名、自动识别建议或之前的“满意”不能代替选择，不把本批选择自动设为长期默认。
- 未指定展示方式时，优先展示商品全貌或佩戴关系；局部特写可作为明确标注的备选，不能悄悄替代全貌。源图未包含完整商品时先说明，再确定是否接受局部或更换素材。
- 必须保护的是所选商品及本次要求展示的特性；头部、手部、其他服饰按展示需要保留，不要求所有品类都完整保留人像。商品细节图与商品全貌图分开判断。
- 无法同时满足无白边与必须保留区域时，说明具体冲突并询问；不自动改成补白、拉伸、切掉必要商品部分或改背景。
- 单次任务明确允许补白或拉伸时，可作为本次参数执行；不自动改动长期习惯。
- 一次性调整与长期偏好分开记录。含糊反馈或与旧习惯冲突的反馈，先问清范围。每批反馈、修改前审批、异常手动回退和保留3个生效版本继续执行。

## 按商品规划取景

| 本批主要商品 | 优先突出与保护 | 取景判断 |
|---|---|---|
| 上衣／外套 | 领口、肩线、衣身、袖型、下摆；按本次卖点突出Logo、拉链、口袋、面料等 | 全貌图应保留需要展示的衣身与袖型；细节图可集中于选定部位。头部与裤子可按画面需要出画，不能为了保脸而切掉重要衣摆。源图未拍到的衣摆不能补造或声称完整保留。 |
| 裤子 | 腰头、臀裆结构、裤型、裤线、侧袋与裤脚；按卖点选择 | 全貌图优先腰头到裤脚，避免膝盖或裤脚被随意切断；头部与大部分上衣可出画。局部面料／口袋细节须标明。 |
| 眼镜／雪镜 | 镜片、镜框、镜腿／镜带及其连接，保留展示佩戴关系所需的面部 | 可用佩戴半身或镜片特写，按本次需求和原图判断；无关手臂与腰腿可出画，扶镜等关键动作需保留。不能只对准脸而切掉镜片或镜框，也不自动把半身图统一改成紧特写。 |
| 帽子 | 帽冠、帽檐、Logo；帽带／披风属于卖点时一并保护 | 结合佩戴关系留适量面部，避免为了保脸或固定眼睛位置而切掉帽顶、帽檐。原图已经缺失的部分需说明。 |
| 鞋／靴 | 鞋头、鞋跟、鞋底轮廓、鞋面或靴筒；双鞋／单鞋以本次要求为准 | 保留必要脚踝和裤脚，减少无关上半身；鞋型与本次卖点优先，不能只保留脚或脚踝而裁掉鞋。 |
| 全身穿搭 | 头脚、服装组合与关键动作 | 保留完整穿搭关系，无法同时铺满与保全时说明冲突，不能借商品突出而改成局部。 |
| 自定义或多个商品 | 按用户指定的主次和展示特性 | 多个品类未给主次时先问清，不把互相冲突的保护要求自动全部叠加。 |

上述是取景目标，不是固定坐标或统一占比。先看每张图的朝向、遮挡、源图边界与目标比例，再规划；优先留出商品边缘距离和必要视线／动作空间，避免裁切线经过应展示的细节。源图缺少目标商品时先说明，不自行换品类。


## 数据包交付
- 用途区分主图和场景图，不根据800/1440判断类型；本轮不操作白底图。
- 先分main主图或scene场景；main预设800×800、1440×1440、750×1000，scene预设750×1000、800×800、800×1200，均支持多选及自定义，只出本批所选。截图每5张不是固定图数。
- 图片默认每size独立1—N编号，不再询问固定图片命名；PSD默认款号_尺寸，每款每尺寸一份且内部1—N。告知默认方案，用户明确自定义图片/PSD命名时再覆盖；naming_source只表示配置来源，不伪称真人授权。
- 未明确改格式时，已有PNG仍输出PNG保留原alpha，JPG/JPEG仍输出JPG；已有PSD未指定成品图片格式时默认JPG并告知，透明部分按JPG白底合成，需要透明可选PNG，不新增格式必填项。
- JPG/PNG成品均不超过500000字节；PSD和说明文本不受此限制。
- 每款每个所选尺寸一个PSD，内含该款N张图，层/组名1—N可隐藏切换，默认仅1可见。主图和场景图均可直接使用JPG、PNG等照片或已有PSD，同单照片与PSD不混合；默认Python调整尺寸并额外交付对应尺寸PSD。照片PSD用未压缩渲染像素构建，无需先把输入照片转存PSD。
- PSD默认用Python输出，当前输入支持平坦纯像素图层和位图蒙版，不支持已有group，包括本包输出1—N分组PSD再次输入。复杂文字、智能对象、矢量、效果或组等无法安全保留时提示限制，让用户选PS或提供兼容副本，不能假支持、自动flatten或切换Photoshop；也不能把从JPG重建的PSD说成恢复了原生可编辑结构。
- 一份PSD含多图不自动拆job。用户明确取01—05等图层/颜色范围后，每张建立同一input、不同source_layers的job；白底选对应商品层和真实背景层，透明不加背景，纳入整批分尺寸预览。未选范围不能自动拆；保留的是所选源层子集，metadata说明不是master全部层。
- 用户选PS且有source_layers时，只对受支持平坦pixel源先由Python按原尺寸无缩放提取，再由PS执行目标重采样；复杂或group源的按层取图暂需先在PS拆成独立源文件，不能忽略selector。
- 对PSD输入或含PSD交付的业务任务，按实际source_viewport算scale=max(目标宽/取景宽,目标高/取景高)。先聚合整轮scale>1且未选的风险项，按尺寸/明确范围一次提示倍率及可能模糊、细节变软，建议使用Photoshop（PS）放大，由用户选择PS或继续Python；PSD格式本身不提升清晰度，建议不代表自动选择，齐备前不生成该轮任何目标尺寸预览或正式输出，返回requires_backend_choice，不偷偷默认Python。不是1440固定阈值，PS也不保证找回缺失细节。安装合成PNG/无PSD几何诊断不作为业务决策。
- 用户已明确选定本批具体输入、实际裁切与尺寸的Python或Photoshop时，记录真实原文、basis和适用范围并复用，不重复询问；源文件或内容、裁切、尺寸变化后选择失效。Python默认和风格沿用授权都不代替未作出的放大选择，也不能学成永久自动放大。当前帽子Python1440授权仅适用于该次已确认的具体任务。
- 本机Photoshop COM原生路径尚未通过实机验收，该事实不阻断已支持的Python路径；用户选PS后若环境不可用则如实失败，不能自动退回Python。
- 目录分图片和源文件，附使用提示词、本批处理说明。
- 主图/场景按用途和品类提炼反馈经验，不把案例坐标或占比变成无条件固定规则；长期更改仍先验证审批。
