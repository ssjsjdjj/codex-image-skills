# 3.4商品主体选择与构图规划

## 入口选项

开始本批裁切规划前确定主要商品。没有明确选择时，用一次用户输入问题提供“上衣／外套、裤子、眼镜／雪镜、帽子、鞋／靴、全身穿搭”，同时支持自由输入自定义品类或主次；不要把工具预选项当作已提交答案。已给出的素材、尺寸、数量和输出位置不重复询问；缺失信息可与主体问题一起收集。

用户已明确“突出上衣”等品类时直接采用；明确“继续上一批参数”且上批主体已确认时可沿用。目录名和视觉识别只能作为建议，不能据此假定这张戴眼镜的照片一定卖眼镜。没有回复时可继续盘点素材，不能自行按第一个选项批量出图。

本批选择只记录到本批任务说明，不直接写入长期个人规则。品类偏好的长期变化继续按feedback-workflow.md中的草案、验证、确认流程处理。各品类已批准的取景习惯以当前账号personal_prompt.md为准。

## 从选项到具体裁切

1. 先分main/scene和对应尺寸多选；看每张原图及本次要求，写清主要商品、展示特性、必须保留与可出画部分。未指定展示方式优先全貌或佩戴关系，细节仅明确标注备选；源缺完整商品先说明，不能暗改局部。用户只说品类时按已批准习惯规划，只对影响取景的歧义追问。默认规划整批各所选尺寸，不等待每张单独确认才规划下一张。
2. 逐图观察商品位置、朝向、遮挡与源图边界。不得把品类直接映射为固定y焦点、放大倍数或统一裁切框。相同机位可分组，但检查每张商品是否仍完整。
3. 把实际商品范围和必要动作换成原图归一化坐标，使用已有crop_box/focus/subject_box/protect_box。必要商品部分必须落在保护范围内；不能为了绕过冲突而缩小保护框。不要把所有人物头手和旁边的配饰默认设为必保。
4. 检查目标比例、等比、不新增白边和完整保护。需要的全貌超出方形可容纳范围时，展示具体冲突及候选取舍，由用户决定；源图本来没拍到的商品部分不能恢复。用户只授权改尺寸时不生成背景、不抠图、不调色。
5. 目标预览前按实际source_viewport评估scale=max(目标宽/取景宽,目标高/取景高)。PSD输入或含PSD交付业务先聚合本轮所有scale>1且未选项，按size/明确范围一次提示倍率和可能模糊、细节变软，建议Photoshop（PS）放大，由用户选择PS或继续Python，齐备前不生成该轮任何目标预览。不是1440阈值，PS也不保证找回细节。默认Python不代表同意放大；同输入/内容/裁切/尺寸真实选择可复用，依据变化失效。安装合成PNG/无PSD几何诊断不作业务后端选择。
6. 风险选择齐备后，只生成当前候选的一张原图/目标对照预览，标注尺寸、该尺寸内编号及主体取舍。当前张经真实确认后才生成下一张；修改后刷新当前预览和digest，必要时重选后端。全批逐张确认后正式输出；不使用整批确认或风格授权跳过。批末只询问一次反馈。

## 本批说明示例

```json
{
  "product_focus": {
    "category": "眼镜／雪镜",
    "emphasis": "镜片与佩戴关系",
    "must_keep": ["完整镜片和镜框", "必要镜带连接"],
    "may_crop": ["与商品无关的手臂", "腰腿"]
  },
  "jobs": [
    {
      "input": "<实际原图路径>",
      "size": "800x800",
      "crop_box": "<根据这张图确定的框>",
      "protect_box": "<根据本张商品确定的框>"
    }
  ]
}
```

product_focus是供Codex规划和复核的任务说明；裁切器不识别商品品类。上例的坐标占位符不是可直接运行的任务单。实际出图须填入有效数值坐标，并通过个人规则检查；不得使用不存在的--category选项，也不能只加品类字段而沿用无关的旧取景框。

## 常见情况

- “帮我把裤子图改800×800”：直接按裤子规划，头部无需默认保全；仍先看源图是否包含腰头、裤脚。
- 素材目录叫“雪镜”，用户选择“上衣”：以上衣为主体；雪镜可以成为非重点部位，不能用目录名覆盖选择。
- “上衣和裤子都要”：若未给主次，确认是完整穿搭还是某一件为主。
- 选眼镜后用户只说“这张B版好”：视为本次构图选择，不能自动规定所有眼镜以后都用B版的坐标。
