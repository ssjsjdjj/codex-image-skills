# 案例库：自动整理与引用

本文件规定如何从真实审核记录生成案例，以及如何把案例当作参考。实际案例由脚本生成在项目目录的`case-library/case-reference.md`和`case-library/case-index.json`；本技能包不预置虚构的业务案例。

## 项目目录与触发时机

把每个审核版本保存为`reviews/*.json`，原稿与返稿保留可访问位置。记录`reviewed_at`（含时区的ISO 8601时间）、`product_category`和`product_name`，以便排序和检索。取得主管决定、补齐问题关闭证据或修正旧记录后执行：

```text
python scripts/build_case_library.py path/to/project/reviews --out-dir path/to/project/case-library
python scripts/search_cases.py path/to/project/case-library/case-index.json --category 上衣 --dimension product_visibility --query 主体遮挡
```

首次审核前，若已有团队案例库，可先检索其中同品类、同维度、相似场景。脚本每次从原始JSON重建索引，重复运行结果一致；旧记录更正或撤销批准后，重新运行会更新或移除相应案例。案例文件是派生视图，审核JSON和原始视觉文件才是事实来源。不要直接编辑生成的案例文件；先改源记录再重建。

## 自动入库条件

脚本只提取必改问题（关闭记录中的`kind=required`）被解决的案例；可选建议不入库。同一`project_id`和稳定问题ID必须在较早的有效记录中为`open`、`partial`或`pending`，较晚记录为`closed`，且后者有`closure_evidence_ids`。较晚记录必须有主管已记录的`direction_approved`或`final_approved`。项目所有版本均须有可用的`reviewed_at`、`product_category`和`product_name`；时间须含时区，审核ID和审核时刻在项目内不得重复。脚本按审核时间排序并校验相邻版本的问题衔接。

更晚版本若将同一问题重开为`open`、`partial`或`pending`，或标为`dismissed`，旧解决案例撤下；重开后须再次关闭并获批准才恢复。记录读取、结构或版本衔接校验失败时不开始更新索引。缺少元数据字段会跳过整个项目并写入`skipped_projects`；已填写但无效的元数据属于校验失败。已有未解决历史、当前已关闭但尚未获主管批准的必改问题，按项目和问题ID去重，写入`skipped_candidates`，保留最近的关闭审核ID及原因；后续批准、重开或否定后从该统计移除。两类统计同时展示在可读参考和命令行结果中。

案例ID由`project_id`与问题ID稳定生成；同一问题多次解决只保留最新一次已批准且目前仍关闭的解决案例。索引保留前后`review_id`、版本、原文件位置、问题描述、修改动作、验收条件、前后证据及主管决定，不复制图片和个人资料。项目路径和图像的访问权限沿用原文件，不因进入索引而扩大。

案例的修改前记录取该次解决过程最早的未解决版本，修改后取获批准的关闭版本。后续版本持续`closed`或省略已关闭问题时保留已有案例，不自动改写为后续文件；重开再解决后才替换这组前后证据。脚本只检查证据字段和引用关系，图片可访问性、实际哈希及证据是否足以证明解决仍需打开原稿核验。输出JSON和Markdown分别替换，跨文件写入不保证共同事务；写入报错后修复路径或权限并重建两份文件。

## 审核时怎样引用

按品类、评分维度、关键词检索，并打开索引指向的前后审核记录和原视觉文件。引用时写案例ID、可比点与差异点、前后画面位置，说明本稿为何仍需相同或不同的修改。过时的品牌/平台规则须以当前已确认规则为准；不能把历史案例当作新品的商品事实或自动扣分依据。找不到可核验原稿时，仅把案例作为待核查线索，不作为正式证据。

`search_cases.py`的筛选条件同时生效：`--category`为忽略大小写的品类子串匹配，`--dimension`为维度ID精确匹配，`--query`在品类、商品名、问题描述、修改动作、验收条件及维度ID中做忽略大小写的连续子串匹配，不进行分词、语义搜索或相似度排序。不传筛选条件则列出全部案例。索引结构损坏会报错；无匹配仍正常返回0条。检索和构建成功返回0，已捕获的输入或文件错误返回1，参数用法错误返回2。

`case-reference.md`供模型按需阅读和`rg`检索；`case-index.json`供脚本检索。两者均保存在项目本地案例目录。
