# 飞书审核表同步契约

本引用仅在用户要求同步，或项目已有持续有效的目标表授权时加载。支持具备相应权限的飞书连接器、MCP工具或飞书多维表格OpenAPI；本技能不假定某个连接器已经安装，也不持有凭证。群机器人Webhook只适合消息通知，不用于审核表增改与回读。

## 最小接口

连接工具应能读取目标表字段定义、按审核ID查找记录、创建或更新记录、按远端记录ID读取，并返回可核对结果。实施前确认目标多维表格的`app_token`、`table_id`、授权范围和字段类型。凭证走连接器或安全环境配置，不写进SKILL.md、审核JSON或聊天输出。

建议至少保存项目ID、审核ID、阶段、逻辑版本、实际文件名、规则版本、九项原始分及总分、AI建议、主管决定、问题清单或其可访问链接、同步状态。对多轮跟踪，优先采用“项目、版本审核、问题”三类记录或相应关联表；现有单表可先加唯一审核ID及结构化明细链接，避免用更新覆盖旧版本。

## 写入流程

1. 运行本地校验并保存本版本记录。读取目标表字段清单，将数值、日期、枚举、附件和链接映射到实际字段类型；未知值使用空值及缺失原因字段，不把“待补”写入数值或日期字段。
2. 按`review_id`查询目标表。同一审核ID已有记录时更新；没有时创建。若请求超时或结果不明，先重新查询，不盲目创建第二条。
3. 返回远端`record_id`后读取该记录，比较审核ID、项目ID、阶段、逻辑版本、总分、结论和问题清单关联。针对接口规范化后的值做语义核对。
4. 只有回读一致才将`sync.status`写为`synced`，并记录`record_id`、回读时间和已核对字段。若权限、接口或字段映射失败，标`failed`并保留错误摘要；尚未尝试或等待连接时标`pending`。保留本地完整审核记录供后续重试。

不以网络错误推断写入失败或成功；不要无限自动重试。跨表写入不一定原子化，部分成功时逐条记录远端ID和待补项，再依据审核ID恢复。主管确认可在飞书更新，但必须保留主管原始确认记录和Codex原建议，不静默覆盖。

飞书官方多维表格OpenAPI支持记录创建、更新与读取，具体权限和字段格式须以目标表与当前接口文档为准：[创建记录](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-record/create)、[更新记录](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-record/update)、[读取记录](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-record/get)。
