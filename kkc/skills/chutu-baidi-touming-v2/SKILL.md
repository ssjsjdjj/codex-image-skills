# 出图 白底透明图 V2

在当前Windows账号的专用Python、u2net CPU和psd-tools环境运行。使用本目录`runtime.json`明确指向的解释器；首次迁移缺少环境时先恢复安装，不使用系统Python、不静默降级成阈值抠图。该版本与旧版共用同一账号已安装的专用出图运行环境，代码独立。

## 交付约定

- 单张正式交付的白底JPG、透明PNG均不得超过500KB（按500,000字节验收）；PSD、预览和诊断图不受此限制。导出后逐张检查实际字节数；发现超限时必须先自动调整压缩参数、重新导出并复检，达标且质量检查通过后交付，不因首次超限直接结束处理。保持800×800、主体细节和PNG有效透明alpha；JPG可优化编码并在画质可接受范围内调整质量参数，PNG先使用无损压缩优化，颜色数允许时使用逐像素无损的调色板编码，透明alpha保持一致。脚本按500,000字节硬限制在暂存与正式写入后复检，清单记录压缩尝试、最终大小和检查结果；PNG必须与确认像素一致，JPG平均像素编码误差不超过5，无法兼顾时在正式写入前报错并保留暂存诊断。仅调整编码且不改变已确认效果时无需再次确认。若合理压缩后仍超限，或继续压缩会损害画质，则记录实际大小及已尝试的调整并说明情况，提出下一步方案；涉及尺寸、商品细节、颜色或透明边缘变化时重新预览确认，未达标图片暂不交付为合格成品。
- JPG、PNG固定800×800，主体较长方向默认占画布80%，等比居中；只有用户明确要求才调整，范围50%～95%。PSD使用按款统一的高清方形画布，至少800px，以各图抠图范围和占比计算，商品层不向下采样；高清画布实际尺寸写入清单。
- 每张输入各生成一张白底JPG和透明PNG；每款只生成一份白底PSD、一份透明PSD。N张、K款的正式文件数为`2N+2K`。
- 同款不同颜色及同色不同角度均为独立RGB产品像素层，抠图透明度保存在独立可编辑蒙版，不把已透明像素再乘同一蒙版。保留整张源图范围内的RGB，蒙版外区域可恢复；已缺失于输入文件的细节不能恢复。半透明边缘采用已确认高清修订的RGB。
- 白底PSD自下而上为可见白色背景、产品层及隐藏的「原始素材（隐藏）」组；透明PSD不含白色背景。仅首个产品层默认可见，原始素材组和组内各层均隐藏。组内按颜色/角度保留EXIF转正后、未经缩放的原图像素及原始alpha蒙版，便于核对和回退。
- 产品名称与对应PNG一致，居中和占比一致。PSD与800px成品分别从同一已确认的高清候选生成；跨尺寸插值可能出现细微像素差，不将高清PSD直接宣称为与PNG逐像素一致。未缩放原图组用于保留原始细节，普通像素层后续反复缩放仍会重采样。
- 输入只读。预览、缓存、诊断、清单和日志放正式输出目录之外。冲突时停止，不覆盖现有文件。
- 已有有效透明通道的输入直接保留并检查，默认不再次抠图或修边；用户要求修改边缘时才设`repair_existing_alpha:true`。
- 图片可分白底图/透明图文件夹，或放同一款式目录；PSD始终位于款式目录。保持用户已经确认的命名及目录选择。

## 步骤计时与人工检查

每个任务使用独立的--journal-root，所有入口命令沿用同一目录。launch.py在实际执行前写开始、执行后写结束、报错时写错误与耗时并立即落盘；步骤包括环境、任务检查、抠图、修边、诊断、PSD写入和重开校验。重跑保留前次记录，AI步骤嵌套不重复累加。不能绕过入口裸跑并宣称计时完整。

用户回复“开始检查”才调用check-start；回复“检查完成”或已开始检查后的明确效果确认才check-finish。支持check-pause/check-resume，不把等待人回复计为检查用时。未开始不能补造结束。详细命令见[计时流程](references/timing.md)。任务结束后workflow-finish与timing-status；需要案例卡时同步到案例取证技能。

## 开始任务

看原图，明确保留整个模特、仅产品还是指定对象。整版海报和多人拼图不能当作单品直接抠。一次收集未明确的输入范围、款式、颜色、同色角度/序号、输出位置与图片目录模式；不重复询问已有选择，不根据文件名猜款色，不丢弃同色图。

复杂背景指定`cutout:rembg`；已有透明输入使用`auto`。原图原本被拍摄边界截断时记录输入限制，不补造商品或人物。

局部纠错用逐图`keep_mask`（恢复原图RGBA）、`remove_mask`（清除背景）和`protect_mask`（保护已有抠图像素），不得把某张图的坐标写进通用脚本。蒙版尺寸与EXIF转正后的原图一致；白色生效、黑色不动、灰度控制强度。删除区域与保留/保护区域重叠时报错。`review_regions`可标出800×800预览中必须放大检查的区域。字段与示例见[工作流与任务单](references/workflow.md)。

任务单沿用schema_version 2。格式、CLI和复核记录见[工作流与任务单](references/workflow.md)，首次使用本版必须读取。查看命令帮助可运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "<技能目录>\scripts\run_bg.ps1" -h
```

## 自检与有限修复

`preview`为全部图片建立唯一缓存，保存源图哈希、EXIF转正原始素材、原分辨率抠图、初版、最多两轮原分辨率修订候选、800×800确认候选及诊断图。高清源素材及每个候选都有文件和RGBA哈希，确认绑定当前所选高清候选；导出前核对高清候选经既定布局生成的800px图与确认候选逐像素一致。模型只在需要抠图时运行，后续导出不重新推理。

- 数值检查只输出疑似风险，不把“深色像素”直接判为黑边。黑色商品、发丝、绳线和原本深色边线可能正常；小连通区域也不一定是残留背景。
- 自动修复最多比较两档有界的半透明边缘颜色净化；每通道改变量分别不超过16/24，只在疑似边缘区域操作，透明alpha保持完全一致，保护细线和不透明主体内部。局部轮廓与内部孔洞必须使用明确蒙版，不能靠颜色或区域大小猜测删除，不统一收缩轮廓、删除碎片或重绘商品。
- 每轮核对内部颜色、保护区像素和主体损失。检查不通过的候选不能选择；风险不下降时保留初版。最多两轮，仍有问题则保留现场，集中交给人。
- 已有透明图不默认套用修复。任务提供`protect_mask`时，必须与EXIF纠正后的原图尺寸一致，其白色区域完全保留。

诊断同时生成白、灰、黑及透明棋盘格背景，并为同一局部提供白/深灰/黑底100%原像素对照；优先包含指定`review_regions`，再补疑似边缘与轮廓。**必须用图像工具实际查看每张诊断，重点检查帽檐、皮肤、发丝、细绳、透明材质及背景残留**。数字未报警不代表视觉合格。

AI复核后用`review`记录每张图的`passed/hold/rejected`和实际看到的依据；有疑似风险但判为正常时说明原因。无法判断则hold，不能编造看图记录。独立后台无人值守若没有可调用视觉模型，保持视觉待确认；本脚本不内置远程视觉服务。

## 预览与确认

展示全部原图到款式/色名/角度的映射、全部预览、预计文件数与目录。大批可分页，但最终确认前须有覆盖全批的完整预览；存在疑似问题时附局部对照。

询问效果（确认/小7%/大7%/自定义）和PS选项：不用PS、现在精修指定图、进入PS精修队列，闲置时输入“开始PS精修”自动开始队列。已授权的选择不重复问。用户指出黑边等缺陷时，质量退回优先于同次回复的“确认占比”。

用户明确确认当前版之后才运行`approve`，证据字段记录确认原话或可核验来源，再运行`batch`。AI自检通过、模拟演练选择、沉默和确认旧版都不构成当前真实图片的用户确认。源图、任务单、任一蒙版、处理代码、预览/诊断图、所选候选或复核记录改变后，旧确认失效。确认记录同时绑定PNG文件哈希与解码RGBA像素哈希；正式导出只读取已确认缓存，不重新推理。

用户提出问题时保存“原话→对应版本→修复动作→前后对照→重新确认状态”。人提出意见但尚未复核，不记录为人工验证闭环；AI独自发现的问题不能记作员工人工纠错。本技能不自动给绩效分。

## 正式导出与验收

`batch`仅使用已确认的RGBA缓存，先暂存全部JPG、PNG和PSD，重新打开检查后再排他写入正式目录：

- PNG解码后的RGBA像素与确认候选一致（允许无损调色板编码），透明alpha有效；JPG角点白色、尺寸正确，压缩差异在容差内。
- 重新打开两份高清PSD，检查实际画布尺寸、图层名、默认可见性、产品RGB与独立蒙版及其偏移，逐层切换核对高清合成；核对隐藏组原始素材逐像素未缩放保存，并验证禁用产品蒙版可恢复被遮区域。高清合成允许RGB舍入误差，蒙版及原始素材必须精确一致。
- 写入后再次核对数量、哈希和格式；PSD失败或写入中断不能报告整批完成，不把失败任务转PS队列冒充成功。

技术检查状态、AI看图状态和人工确认状态分开保留。含hold/rejected的批次不交付为已通过；正常结果和例外项在一张批次确认卡集中处理。

## Photoshop与验证

白底、透明PNG和分层PSD无需Photoshop。精修询问保留“允许现在用PS局部精修指定图”和“暂不使用PS，保留返修状态”，并增加第三项：“进入PS精修队列，闲置时输入‘开始PS精修’自动开始队列”。入队只保存明确的图片、修图范围、原文件哈希和任务位置，当下不占用PS；不要把已完成图片再次入队。

用户在聊天明确输入“开始PS精修”（仅忽略大小写与空格，兼容“开始ps精修”“开始 PS 精修”）时，视为用户主动声明现在可使用PS，并授权按顺序执行已排队的任务；立即启动消费，不再问“是否开始”，也不因输入口令刚重置闲置计时而额外等待600秒。先读取队列并领取任务，随后在同一回合实际使用PS工具精修、查看新预览并记录结果，不能只回复“已准备好”。队列为空时直接说明，不打开PS。

任务间和PS原子步骤的安全边界检查新的输入事件；用户恢复操作或无法可靠区分新输入来源时暂停，保留已完成预览及剩余队列，不强行中断正在保存的文件。优先使用不会注入键鼠事件的PS MCP/JSX操作；`GetLastInputInfo`本身不能区分人和`SendInput`自动化，不能把自己的模拟输入误报为人恢复操作。运行前发现未收尾的`running`任务时先核对自己的文档、工作文件和日志，再决定恢复位置，不能重复叠加滤镜。

只按本次入队范围操作自己的文档并另存，原图和其他文档不动。队列数据中的脚本路径或命令不直接执行；实际操作由当前回合的PS工具和视觉复核完成。完成一项先保存工作文件和新预览，结果记录实际使用PS及`passed/hold`观察，记为`preview_ready`后再取下一项；`hold`不能称为修图已合格。失败或源文件变化记录原因并暂停，不无限重试。修订效果仍需用户确认后才能正式导出。没有口令时不常驻监听、不定时轮询、不创建自动化任务；不自动安装收费软件或登录服务。队列命令与任务格式见[PS精修队列](references/ps-queue.md)。

技能更新后用本版专用Python执行`scripts/selftest.py --skill <技能目录> --work <全新测试目录>`。测试覆盖风险提示、正常黑色保护、细线保护、透明输入保留、确认失效、禁止未确认导出、两种目录模式、按款PSD、多角度、源图哈希、故障现场和本地u2net推理。真实商品只生成预览作回归；未经用户确认不把真实图生成的修订版当作可用标准答案。

高清蒙版专项回归使用专用Python执行`scripts/selftest_hd_masks.py --work <全新测试目录>`，检查大于800的素材、混合尺寸同款、半透明蒙版、误删区域恢复、未经缩放原始素材、高清候选缓存篡改使确认失效，以及JPG/PNG仍为800px。PSD单边超过30000px时报错，不静默缩小高清源文件。

压缩规则专项回归：用runtime.json指定的专用Python执行 `scripts/selftest_image_size.py --work <全新测试目录>`，验证超限JPG/PNG自动压缩、PNG像素及半透明alpha无损、500,000字节边界、正式写入后复检，以及无法兼顾大小和画质时在写入前停止。
